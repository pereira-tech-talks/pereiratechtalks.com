## Executive Summary

_Fill in after the first PTT v3.0.0 audit run._

PTT v3.0.0 is engineered for AEO from the ground up:

- **Native Markdown twins** for every public HTML page (`.md` URLs and content negotiation via `Accept: text/markdown`).
- **JSON-LD structured data** on every page (Organization, Event, BlogPosting, BreadcrumbList, CollectionPage, Person, ContactPage).
- **Discovery files**: `llms.txt`, `llms-full.txt`, `robots.txt` with explicit AI crawler allowances, `.well-known/api-catalog`, `.well-known/mcp/server-card.json`.
- **OpenAPI spec** at `/openapi.json` for public JSON endpoints.
- **Hreflang** alternate links for every bilingual page.
- **Sitemap with `lastmod`** auto-generated by `@astrojs/sitemap` (excluding `/internal/*`).
- **RSS feeds** for English (`/rss.xml`) and Spanish (`/es/rss.xml`).

## What This Audit Should Verify

### Crawlability

- [ ] `robots.txt` allows GPTBot, ClaudeBot, PerplexityBot, Google-Extended, etc.
- [ ] `/internal/*` returns `noindex` and is excluded from production builds.
- [ ] No accidental login walls or rate limits on public content.

### Indexability

- [ ] `sitemap-index.xml` includes every public page (blog, slides, meetups, events, Tech Days, verticals, speakers, talks, contributors, sponsors, channels).
- [ ] Each entry has a `<lastmod>` reflecting the latest content update.
- [ ] Hreflang alternate links present on every bilingual page.

### Structured Data

- [ ] Organization schema on every page.
- [ ] Event schema on Pereira Tech Day edition pages and meetup pages.
- [ ] BlogPosting schema with `author.image`, `dateModified`, `inLanguage`.
- [ ] Person schema on speaker and contributor pages.
- [ ] BreadcrumbList schema on all listing/detail pages.

### Content Quality

- [ ] Every blog post and meetup recap has a complete frontmatter (title, description 130–160 chars, pubDate, heroImage, tags, author).
- [ ] No placeholder text (`[AUTHOR:`, `[TODO:`, `[TBD]`).
- [ ] Spanish content has correct diacritical marks.

### Discovery Files

- [ ] `public/llms.txt` reflects current content surface.
- [ ] `public/llms-full.txt` describes all major collections and per-edition branding.
- [ ] `.well-known/api-catalog` and `.well-known/mcp/server-card.json` are valid.

### Markdown for Agents

- [ ] Every page has a `.md` twin.
- [ ] Content negotiation (`Accept: text/markdown`) works via Cloudflare middleware.
- [ ] Markdown bodies preserve code blocks and links exactly.

### Performance

- [ ] Lighthouse 100 (or ≥ 95) on Performance / Accessibility / Best Practices / SEO for: homepage, a blog post, a meetup recap, a Tech Day edition page, the slides catalog.
- [ ] Bundle size budget passing (`pnpm run search:budgets`).

### E-E-A-T Signals

- [ ] Authors have bilingual `role` and `bio`.
- [ ] Sponsors page lists current and historical sponsors with what each paid for.
- [ ] Contributors page lists organizers, mentors, recurring speakers.
- [ ] Real-world organization signals: registered domain, contact methods, governance docs.

## Methodology

1. Run `pnpm run build` and inspect `dist/` artifacts.
2. Use `curl -H "Accept: text/markdown" https://pereiratechtalks.org/<page>` for content negotiation checks.
3. Run Google's Rich Results Test on each schema-bearing page type.
4. Run Lighthouse on a representative URL set (homepage, blog post, meetup, Tech Day, sponsors).
5. Run the LLM citation tests in [`CHECKLIST.md`](CHECKLIST.md) Section 5.
